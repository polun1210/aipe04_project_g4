# 人工校對示範

- 開發伺服器：開啟 `/review-demo`，或由兩個人工校對頁的「使用示範資料練習人工校對」進入。
- 正式建置預設停用並將此網址導回首頁。只有專用示範部署在建置時明確設定 `VITE_ENABLE_REVIEW_DEMO=true` 才開放；不要在一般正式部署設定此值。
- 示範頁使用獨立 Vue 應用、Pinia 與記憶體路由，沿用原有校對元件和欄位驗證。只有隔離應用提供示範 context，一般頁面加上 query 參數不會啟用。
- 沿用專案 `04_drug_draft.json`、`04_supplement_draft.json`，只在記憶體副本標記 `stub-review-demo`，不執行 OCR／AI、不附原始照片。正常候選仍透過既有目錄與 lookup GET API，沒有新增藥品假清單。
- 「其他／不確定」仍沒有正式候選。僅在隔離示範流程允許完成本機校對後繼續；一般流程的評估防護不變。
- 保健食品仍須完成必要欄位與需要確認成分的鎖定；範圍外成分維持折疊、只告知及免鎖定。
- 示範下一步只顯示既有 `08_report.json`。畫面明示「示範資料，非實際個人化評估結果」，不隨輸入重算、不是健康建議。沒有產品、評估、報告建立或儲存請求，不寫 localStorage。
- 按「結束示範，返回一般流程」、離開或重新整理會銷毀示範狀態。正常流程的既有資料保留；重新進入示範只載入原始樣本。
- `npm run test:medicine-search-browser` 驗證一般流程、桌機／手機示範流程、零 POST、隔離清理及兩種實際 production 建置開關。
