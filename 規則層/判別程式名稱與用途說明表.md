# 判別程式名稱與用途說明表

適用於目前的本機試用版 `營養素與用藥評估試用版/index.html`、`app.js`，並對照先前的 Python `規則.py`。表格中的「使用段落」是程式流程或函式名稱，方便查找；同一概念在 Python 與 JavaScript 中可能使用不同名稱。

## 1. 使用者輸入名稱

| 名稱（Python／網頁 JS） | 中文意思及填寫方式 | 使用段落 |
|---|---|---|
| `AGE`／`age` | 年齡，填 19 歲以上整數；決定 19–30、31–50、51–70、71 歲以上的參考值分區。 | 輸入區 → `readState()` → `calculate()` 選擇 `ageIndex` |
| `SEX`／`sex` | 性別，填「男」或「女」；選擇表格中對應數值。 | 輸入區 → `selectedReference()` |
| `ACTIVITY`／`activity` | 活動強度：「低」、「稍低」、「適度」、「高」；用來選膳食纖維參考值。71 歲以上沒有「高」的表格數值。 | 輸入區 → `calculate()` 的膳食纖維計算 |
| `DAILY_ENERGY_KCAL`／`energy` | 全天熱量，單位 kcal；可留空。填入後才能計算碳水化合物、脂質等佔總熱量的百分比。 | 輸入區 → `calculate()` 的 `percentEnergy` |
| `MEDICATIONS`／`medications` | 目前使用的藥品成分名稱清單；沒有可留空。網頁可逐一加入藥品。 | 輸入區 → `canonicalMedication()` → `trigger()` |
| `PRODUCTS`／`products` | 一筆或多筆保健品資料；每筆各有產品名稱、每日份數和營養素明細。 | 輸入區 → `readState()` → `calculate()` 加總 |
| `name` | 保健品名稱；方便辨認輸入及錯誤訊息，不參與數值計算。 | 產品輸入列 → `calculate()` |
| `servings_per_day`／`servings` | 每天吃幾份。每份含量乘上此值，才是該產品的每日提供量。 | 產品輸入列 → `calculate()` 加總 |
| `nutrients`／`rows` | 每種營養素的輸入集合；網頁每一列包含 `nutrient`、`amount`、`unit`。 | 產品輸入列 → `convert()` → `totals` |
| `nutrient` | 營養素或規則成分的名稱，例如「鉀」、「維生素 C」或「紅麴」。 | 產品輸入、參考值查找、交互作用配對、報告 |
| `amount` | 每份含量的數字。**空白代表未記錄；`0` 代表已確認沒有該成分。** | 產品輸入列 → `convert()` → 報告狀態 |
| `unit` | 含量的原始單位，例如 `g`、`mg`、`µg`；可輸入支援的中文別名。 | 產品輸入列 → `parseUnit()` → `convert()` |
| `MEDICATION_ELEMENTAL_PER_DAY`／`medicationElemental` | 某些已輸入藥品額外提供的「每日元素鈣／鎂」量；填元素重量及單位，不填化合物總重量。 | 進階輸入 → `calculate()` 的藥品元素量加總 |
| `CONTEXT`／`context` | 交互作用的補充條件，例如是否長期用藥、是否同時服用、菸鹼素型態等。 | 進階輸入 → `trigger()` |

## 2. 資料來源與固定規則名稱

| 名稱（Python／網頁資料） | 中文意思 | 使用段落 |
|---|---|---|
| `BASE_DIR` | Python 程式檔所在資料夾；在 Notebook 中改用目前工作資料夾。網頁版不使用這個路徑。 | Python「測試輸入區」的路徑設定 |
| `RULE_DIR` | Python 尋找「規則層」資料夾的位置。網頁版已將規則資料包進 HTML，開啟頁面時不用讀取此資料夾。 | Python 檔案定位；網頁版無對應執行步驟 |
| `REFERENCE_MD` | 成人每日營養素參考值檔 `規則.md`。 | Python 讀取參考值；網頁資料的 `referenceRows`、`fiber` |
| `INTERACTION_MD` | 藥物與營養素交互作用規則檔。 | Python 讀取用藥規則；網頁資料的 `rules` |
| `PDF_SOURCE` | 第八版營養素總表 PDF 的人工核對來源；Python 執行時不解析 PDF。 | 來源核對；網頁 `sources` 註明依據 |
| `data`／`ruleData` | 網頁載入的整包固定資料。`ruleData` 嵌在 HTML 中，`data` 是 JS 解析後的物件。 | `init()` 載入 → `calculate(input, data)` |
| `referenceRows` | 各成人年齡層、性別的參考值資料列。 | `calculate()` 查表與計算比例 |
| `fiber` | 依活動強度、年齡、性別選出的膳食纖維參考值表。 | `calculate()` 膳食纖維段落 |
| `units` | 各成分在程式內採用的統一單位，例如維生素 C 用 mg。 | `convert()`、`totals` 初始化 |
| `UL`／`ul` | 部分營養素的每日上限值；未列 UL 的項目不自行補值。 | `calculate()` 的 `ulStatus` 判別 |
| `PERCENT_ITEMS`／`percentItems` | 需依總熱量換算百分比的項目及每克熱量係數。 | `calculate()` 的 `percentEnergy` |
| `RULE_MODES`／`rules[].mode` | 每條交互作用規則的觸發方式。網頁 `rules` 也包含藥名、營養素、提示級別、文字與原規則行號。 | `trigger()` 用藥判別 |
| `rules[].medication`、`rules[].nutrient` | 一條規則要比對的藥品與營養素名稱。 | `trigger()` 前的規則篩選 |
| `rules[].message`、`rules[].line` | 觸發後顯示的提醒文字，以及來源規則檔中的行號。 | `reportItem()` 交互作用報告 |
| `MED_ALIASES`／`medicationAliases` | 藥品別名對照，例如「氯沙坦」對應 `Losartan`。 | `canonicalMedication()` 名稱統一 |
| `MASS_ALIASES`／`massAliases` | 重量單位別名對照，例如 `ug`、`mcg`、`微克` 對應 `µg`。 | `parseUnit()` 單位辨識 |
| `MASS_TO_MG`／`massToMg` | 每個重量單位相當於多少 mg，作為單位換算的中介值。 | `convert()` 換算 |
| `EQUIVALENT_ALIASES`／`equivalentAliases` | `RE`、`α-TE`、`NE` 等當量標示的別名。這些型態須一致，不能只按重量直接互換。 | `parseUnit()`、`convert()` |

## 3. 計算及判別時使用的名稱

| 名稱 | 中文意思 | 使用段落 |
|---|---|---|
| `readState()` | 從網頁欄位收集年齡、用藥、產品及進階條件。 | 輸入 → 計算前 |
| `parseUnit()` | 辨識輸入單位及當量型態；`IU` 不做通用換算。 | 單位處理 |
| `convert()` | 將一筆含量換成該成分的統一單位；空白回傳 `null`。 | 單位處理 → 每日加總 |
| `canonicalMedication()` | 將已知藥品別名轉成規則表採用的標準名稱。 | 用藥輸入 → 規則比對 |
| `calculate()` | 主判別函式：檢查輸入、換算與加總、套用交互規則、組成結果。 | 整體計算流程 |
| `ageIndex` | 成人年齡分區索引：`0`＝19–30、`1`＝31–50、`2`＝51–70、`3`＝71 歲以上。 | `calculate()` 選參考值及部分 UL |
| `totals` | 所有已知來源按營養素加總後的每日量；多款產品會合併。 | `calculate()` 加總 → 規則與用量判別 |
| `unknown` | 尚有空白或未填含量的營養素集合。即使其他產品提供了部分數值，總量仍可能不完整。 | `calculate()` 加總 → `pending`／`unknown` 結果 |
| `present()` | 判斷某營養素為「已知正值」、「待確認」或「沒有正值」。 | `trigger()` 前的成分狀態判別 |
| `trigger()` | 依藥名、營養素、規則模式與進階條件，決定是否觸發交互作用。 | 用藥交互作用判別 |
| `hits` | 已符合觸發條件的規則，按營養素分類。 | `trigger()` 之後 → `risk` 結果 |
| `pending` | 相關藥品已輸入，但關鍵條件未知、尚不能判為已觸發的規則。 | `trigger()` 之後 →「規則條件待確認」 |
| `selectedReference()` | 從同一格的「男／女」數值中選出使用者對應的參考值。 | 用量判別 |
| `target`、`ratio` | `target` 是選出的每日參考值；`ratio` 是已輸入來源的每日量 ÷ 參考值 × 100%。 | 用量判別 → 報告百分比 |
| `percentEnergy` | 已輸入成分換算熱量後，佔使用者所填全天熱量的百分比。 | 用量判別 → 報告熱量百分比 |
| `ulStatus` | 與 UL 比較的結果：`over` 超過、`at` 達到、`null` 尚未達到。 | 用量判別 →「已達或超過上限」 |
| `renderReport()`／`reportItem()` | 把計算結果依交互作用、UL、一般用量、待確認、未記錄等區塊顯示。 | 最後輸出報告 |

## 4. 交互作用條件名稱

這些條件在網頁「進階交互作用條件」填寫；未確認可保留空白。`true`／`false` 分別是「是」／「否」，空白或 `null` 是「未知」。

| 名稱 | 中文意思 | 使用段落 |
|---|---|---|
| `long_term_use`／`longTermUse` | 指定藥品是否長期使用。 | `trigger()` 的 `long_term` 模式 |
| `iron_deficiency_or_poor_response` | 是否已缺鐵，或補鐵反應不佳。 | `trigger()` 的 `ppi_iron` 模式 |
| `nonheme_iron_supplement` | 鐵補充品是否為非血基質鐵。 | `trigger()` 的 `ppi_iron` 模式 |
| `niacin_form` | 菸鹼素型態，區分 `nicotinic acid` 與 `nicotinamide`。 | `trigger()` 的菸鹼素相關模式 |
| `niacin_for_lipids` | 菸鹼酸是否用於降血脂。 | `trigger()` 的 `niacin_statin`、`pravastatin_niacin` |
| `nicotinic_acid_mg_per_day` | 已核對的每日菸鹼酸 mg 數；**僅供交互作用門檻判斷**，一般用量仍填在產品列，避免重複加總。 | `trigger()` 的菸鹼素相關模式 |
| `high_dose_nicotinic_acid` | 是否已確認屬高劑量菸鹼酸情境。 | `trigger()` 的 `niacin_glycemic` 模式 |
| `pravastatin_niacin_dose_confirmed` | Pravastatin 併用菸鹼酸的規則條件是否已核對。 | `trigger()` 的 `pravastatin_niacin` 模式 |
| `monacolin_k_present` | 紅麴是否確定含 monacolin K。 | `trigger()` 的 `red_yeast` 模式 |
| `al_mg_antacid_same_time` | Rosuvastatin 與鋁鎂複方制酸劑是否同時使用。 | `trigger()` 的 `al_mg_antacid` 模式 |
| `calcium_carbonate_with_iron` | 碳酸鈣與鐵是否同服。 | `trigger()` 的 `calcium_iron` 模式 |
| `al_mg_product_iron_warning` | 實際鋁鎂複方產品仿單是否有鐵的警示。 | `trigger()` 的 `al_mg_iron` 模式 |
| `magmitt_product_verified` | 所用氧化鎂是否為規則報告所列的 Magmitt 產品。 | `trigger()` 的 `magmitt_iron` 模式 |
| `cimetidine_high_dose_with_antacid` | 是否符合 Cimetidine 特定高劑量及制酸劑情境。 | `trigger()` 的 `cimetidine_iron` 模式 |

### 規則觸發模式 `mode`

| 模式名稱 | 判別內容 | 使用段落 |
|---|---|---|
| `medicine` | 只要用藥名稱符合，即產生該營養素狀態的提醒；不要求保健品有該成分。 | `trigger()` 用藥狀態規則 |
| `supplement` | 用藥符合且相關營養素已記錄正值時觸發；成分含量未記錄時列待確認。 | `trigger()` 補充品併用規則 |
| `long_term` | 依該藥品是否長期使用判別；未知列待確認。 | `trigger()` 長期用藥規則 |
| `ppi_iron` | 依缺鐵或非血基質鐵補充等條件判別。 | `trigger()` 抑酸藥與鐵規則 |
| `niacin_glycemic` | 依菸鹼素型態、菸鹼酸每日量及高劑量條件判別。 | `trigger()` 降血糖藥與菸鹼素規則 |
| `niacin_statin` | 依降血脂用途、菸鹼酸型態與每日量判別。 | `trigger()` 部分 Statin 與菸鹼素規則 |
| `pravastatin_niacin` | 依菸鹼酸相關條件及 Pravastatin 併用條件是否已核對判別。 | `trigger()` Pravastatin 與菸鹼素規則 |
| `red_yeast` | 依紅麴輸入及是否確定含 monacolin K 判別。 | `trigger()` Statin 與紅麴規則 |
| `al_mg_antacid` | 依鋁鎂複方制酸劑是否與 Rosuvastatin 同時使用判別。 | `trigger()` Rosuvastatin 相關規則 |
| `calcium_iron` | 依碳酸鈣與鐵是否同服判別。 | `trigger()` 碳酸鈣與鐵規則 |
| `al_mg_iron` | 依實際鋁鎂複方產品的鐵警示判別。 | `trigger()` 鋁鎂複方與鐵規則 |
| `magmitt_iron` | 依氧化鎂產品是否為已核對的 Magmitt 判別。 | `trigger()` 氧化鎂與鐵規則 |
| `cimetidine_iron` | 依特定 Cimetidine 劑量及制酸劑情境判別。 | `trigger()` Cimetidine 與鐵規則 |

## 5. 報告標記及縮寫

| 名稱 | 顯示意義 | 使用段落 |
|---|---|---|
| `risk` | 已觸發用藥規則；該營養素直接顯示規則提示及高／中級別，跳過該項的一般劑量評估。 | `calculate()` → 報告「需要注意的交互作用」 |
| `normal` | 已知正值，且未被交互規則攔截；進行參考值及適用的 UL 比較。 | `calculate()` → 報告「保健品提供量」 |
| `unknown` | 存在未填含量，無法確認完整每日總量；不是「確定沒有攝取」。 | `calculate()` → 報告「未記錄或確認 0 的項目」 |
| `zero` | 已確認合計為 0；表示輸入資料中的相關來源未攝取。 | `calculate()` → 報告「未記錄或確認 0 的項目」 |
| `pending` | 交互規則需要的條件尚未確認，暫不判為高／中提示。 | `trigger()` → 報告「規則條件待確認」 |
| `severity` | 規則檔提供的提示級別，例如高、中；代表專題提示優先級，不是個人臨床風險機率。 | `rules` → `reportItem()` |
| `RDA` | 建議攝取量。程式顯示保健品提供量相當於此參考值的百分比。 | 參考值表 → 用量報告 |
| `EAR` | 估計平均需要量。 | 參考值表的碳水化合物項目 |
| `AI` | 足夠攝取量；例如鉀的參考值類型。 | 參考值表 → 用量報告 |
| `AMDR` | 可接受巨量營養素分布範圍，以全天熱量百分比表示。 | 參考值表 → `percentEnergy` |
| `CDRR` | 慢性疾病風險降低攝取量；目前表中的「鈉 CDRR」會以數值及比例呈現。 | 參考值表 → 用量報告 |
| `UL` | 可耐受最高攝取量；程式只在已輸入來源的數值達到或超過時提示。 | `ul` → `ulStatus` → 報告 |
| `RE`、`α-TE`、`NE` | 分別是維生素 A、E、菸鹼素資料中的當量型態；須與參考單位一致。 | 單位輸入 → `parseUnit()`、`convert()` |

**判讀順序：**輸入資料 → 藥名及單位統一 → 每日含量加總 → 藥物交互作用判別 → 沒有已觸發交互規則的項目再做用量比較 → 輸出報告。僅計算已輸入的保健品及指定藥品元素量，不包含一般飲食。
