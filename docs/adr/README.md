# 設計決策紀錄（ADR）

這裡記錄的是第一版開發前，做過的設計決策：**決定了什麼、為什麼、放棄了什麼**。
它們是**下決策時的參考資料**，用來回答「為什麼這裡要這樣設計？」，**不是硬性規定**。
情況變了，或你的模組遇到更好的做法，都可以提出來改。

## 想做的事和某份 ADR 不同，怎麼辦？

以下是建議的步驟，不是強制的：

1. **先讀那份 ADR 的「為什麼」**。很多時候理由就能回答你的疑問；如果理由已經不適用，再往下走。
2. **在群組或 Issue 說明**：想改什麼、和哪份 ADR 哪裡不同、為什麼。不需要已經做完。
3. **和組長討論**，同意後再動手。PR 描述附上討論連結，並寫一句「與 ADR-00XX 不同，因為…」。
4. **同一個 PR 更新 ADR**（不確定怎麼寫，就在 PR 說明，組長合併時補）：
   - **推翻原本的決定**：新增一份 ADR 說明新決定，舊的開頭加註「已被 ADR-00XX 取代」。舊的不刪，讓人知道當初為什麼。
   - **只是補充或修正細節**：直接改原檔。

新 ADR 的檔名是 `00XX-簡短英文標題.md`，編號用目前最大號加 1（編號不一定連續）。
格式參考現有的：一段說明決定與理由，再接 `## Consequences`。
