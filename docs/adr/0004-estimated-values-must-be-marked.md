# 推估值必須可辨識，且用途受限

> 設計決策的參考紀錄，不是硬性規定；想調整請見 [README](README.md)。

保健食品標示常只寫化合物總重（例如「檸檬酸鈣 238 毫克」）而不寫元素純含量。
我們決定**允許系統依化合物型態比率推估元素量**，以換取覆蓋率，
但推估出來的數值必須在資料結構與報告文字兩個層面都與標示值明確區分。

替代方案是完全不推估、缺元素量就退出定量判定。我們拒絕這條路，
因為台灣市售鈣、鎂、鐵產品有相當比例只標化合物總重，
不推估會讓這三項——也就是 UL 最需要被看見的三項——大量落入「無法判定」。

代價是系統會產生一個標示上不存在的數字。這個代價用下列約束抵銷。

## Consequences

- **來源標記為封閉三段**，寫入 schema 的 `elemental_basis` 欄位：
  - `label_stated`：標示已寫元素量（如「含純鈣 50 毫克」）。優先序最高，有則不推估。
  - `estimated`：依比率表換算，同時記錄 `compound_code` 與 `elemental_ratio`。
  - `unknown`：化合物型態無法判定，元素量為空，標記 `requires_user_input`。
    使用者於校對介面無法確認者，該營養素退出定量判定，僅參與重複補充偵測。
- **推估值可以參與上限攝取量比對**，但報告措辭必須揭露估算性質，例如
  「依檸檬酸鈣之元素鈣比例推估約 50 毫克，已達上限的 X%（此數值為系統推估，非標示值）」。
- **推估值不得單獨觸發最高強度的警示。** 同一營養素若另有 `label_stated` 來源，
  一律以標示值為準。
- ADR-0001 的數值忠實性檢查需相應改寫：報告中的數字若不對應結構化欄位即為幻覺，
  此規則維持；但允許對應到 `elemental_basis = estimated` 的欄位，
  且該段敘述必須含估算揭露字樣。這仍是純字串檢查，不需 LLM 當裁判。
- **校對介面必須把估算值與標示值視覺區隔**（不同底色或標籤），並允許使用者直接覆寫。
- 新增一項工作：**化合物元素量比率表**，每條附出處（食藥署原料規格，
  或以分子量計算並標明計算式）。
  鎂與鐵的上限在 DRIs 原文即限定補充劑來源（見 `docs/dris-reference-notes.md`），
  是系統唯二能乾淨比對上限的營養素，比率算錯會汙染最可信的兩條判定。
- 本 ADR 只授權「化合物 → 元素量」這一種推估。
  **推估未標示的成分含量、推估未標示的型態，仍然禁止。**
