# 上限攝取量比對採單日峰值，不採期間平均

> 設計決策的參考紀錄，不是硬性規定；想調整請見 [README](README.md)。

使用者的服用方式不一定是每日一次。「隔天一次」「每週一三五各一包」「吃五天停兩天」
都必須換算成可比對的每日數值。把這些攤平成期間平均（例如每週三次 → 0.43 份／天）
看似合理，但**上限攝取量（UL）是每日上限，不是平均上限**。

以期間平均比對上限會系統性低估風險：一週吃兩次、每次三倍量的使用者，
平均值看起來安全，實際服用當日早已過量——而這正是系統要抓的人。

因此補充劑來源攝取量必須同時保留兩個數值，各自綁定用途。

## Consequences

- schema 中 `daily_intake_amount` 這類單一欄位不足以表達，拆為：
  - `peak_daily_amount`：使用者實際服用當日的攝取量。**上限攝取量比對、接近上限提示一律使用此值。**
  - `average_daily_amount`：期間平均。用於重複補充偵測、一般呈現與跨產品加總的趨勢說明。
- 每日服用者兩值相同，此時不需在報告中區分；兩值不同時，
  報告必須標明上限比較的基準是服用當日，例如
  「你服用當日來自補充劑的攝取量已達上限的 X%」。
- 報告的上限措辭（`docs/prd.md` §六）帶有「服用當日」的限定：
  「你**服用當日**來自補充劑的攝取量已達上限的 X%」。
- 跨產品加總時兩個數值分別加總，不可混用；
  且僅當多個產品的服用日重疊時，峰值加總才成立——
  MVP 不處理「排程錯開」這種情況，一律以最保守方式假設同日服用，並於報告揭露此假設。
- 服用頻率的型態必須是封閉列舉（`daily` / `alternate_days` / `weekly_n_times` /
  `cyclic_on_off` / `as_needed`），才能讓兩個數值都算得出來。
  自由文字頻率無法計算峰值。
